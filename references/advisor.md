# Optional Advisor plugin

Include an **advisor-plugin** recommendation when an Advisor extension is installed. This is separate from a pi-subagents `oracle`/`advisor` agent alias, the parent model, and an external native-CLI reviewer. This skill does not require or install an Advisor extension.

## Inspect without consulting

1. Confirm package identity/version and registration from existing metadata; read that plugin's installed configuration and execution contracts. Confirmed absence means **N/A**. If discovery is incomplete, report unknown rather than absent. Do not enable or install a plugin to complete an audit.
2. Read only the current model key, effort, and executor-disable rules through documented read-only configuration interfaces. Record the resolved source path and validation warnings without prompts, guidance text, credentials, or conversation contents. Prefer the plugin's own loader/normalizer when it can be used without startup or writes; otherwise verify path precedence against its source. Keep parsing, schema validity, model-supported effort, and route availability separate.
3. Distinguish **saved selection**, **loaded runtime selection**, **active tool**, **resolved route/effort**, and **successful execution**. A registered tool or saved key proves neither activation nor provider health. Use a read-only native status surface only if one actually exists; otherwise mark runtime state unqueried. Do not inject commands into an active TUI or call the advisor to inspect it.
4. Add a separate result row: `advisor-plugin | installed/version | current model + effort + source | proposed model + effort | KEEP/PROPOSE/HOLD/BLOCKED/N/A | rationale and unknowns`. Rank eligible candidates under the same benchmark, identity, access, subscription/quota and [bridge](bridges.md) checks as subagent models. Prefer the strongest supported reviewer appropriate to the operator's policy; if maximum supported effort is required, verify that ceiling instead of inheriting a package's preferred default. Preserve current selection with HOLD when the facts do not justify a new assignment. Do not freeze a model winner or silently migrate provider namespaces.
5. Audit stops at the recommendation. Permission to change subagent assignments does not authorize Advisor configuration. A later approved Advisor change names its own file/fields, rereads concurrent state, backs up privately, and preserves unrelated guidance and disable rules. Report saved versus loaded verification and reload requirements. Do not change a native-CLI reviewer policy merely because a plugin is installed.

## Source-scoped example: rpiv-advisor 2.13.9

Reviewed **2026-10-20** against installed `@juicesharp/rpiv-advisor` **2.13.9**. Other versions/plugins need their own contract; these settings are not pi-subagents overrides.

- Configuration is `rpiv-advisor/advisor.json` under the plugin's XDG config root, normally `~/.config`. In this version, absolute or supported tilde-expanded `XDG_CONFIG_HOME` overrides it; relative/blank values use the default. The legacy default-path file is read only if the primary is **missing**. A present malformed primary wins and produces a warning/empty result, not fallback. Report invalid/unreadable separately from an intentionally unset selection.
- `modelKey` stores the exact `provider/modelId`; the parser also accepts its documented legacy key format. `effort` is a separate field. Missing effort sends **no reasoning option**, not an explicit reasoning-off instruction. Restore validates its graded enum; the interactive picker additionally filters the selected model's supported levels. Parsing a file alone does not prove either compatibility or successful restoration.
- `disabledForModels` is a normalized **executor** blocklist, optionally with `minEffort` thresholds. It can make the tool inactive while an advisor selection remains saved. It does not exclude that candidate advisor model globally. Invalid entries and unknown thresholds are handled according to the installed validator; report warnings rather than inventing rules.
- `/advisor` is an interactive **configuration picker**, not a read-only status command. It can persist a selection; cancelling at the effort step can save the picked model without explicit effort. Do not invoke it to inspect status. Read `modelKey`, `effort`, and normalized disable rules without calling save helpers or mutating the plugin's module state.
- The call forwards Pi's resolved conversation branch (including surviving compaction/branch summaries) plus a registered-tool inventory prefix, with a separate advisor system prompt and `tools: []`. It is not guaranteed raw history, redacted content, or filesystem/tool access equivalent to a native CLI reviewer. Consider transcript disclosure, context capacity, latency and repeated consultation quota when recommending.

## Provider compatibility is still required

A plugin's tool-free request does not suppress a provider bridge's native tools. Do not recommend Antigravity's write-capable native loop for a tool-free side-call on the strength of `tools: []`; retain a blocker until a supported safe execution contract is established. Claude Bridge also requires actual advisor-system-prompt projection and context/session compatibility; ordinary parent or subagent success does not prove that payload works. Follow the [bridge contracts](bridges.md), do not switch to an `Ask*` tool as a substitute test, and never trigger a paid consultation just to discover the current selection.
